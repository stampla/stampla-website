The documentation lives next to the code, so it can never drift from
what a release actually does:

- **[Command guide](https://github.com/stampla/stampla/blob/main/docs/commands.md)** —
  every command in detail: the safe-to-format verdict, finding buckets
  and severities, the manifest cache, JSON output, exit codes.
- **[Example setups](https://github.com/stampla/stampla/blob/main/docs/examples.md)** —
  six complete configurations, from a single folder of photos to a
  Lightroom workflow and a naming-scheme migration.
- **[Annotated configuration](https://github.com/stampla/stampla/blob/main/examples/config.toml)** —
  every option, with its default and the reasoning.
- **[Design document](https://github.com/stampla/stampla/blob/main/DESIGN.md)** —
  why it works this way: the naming grammar, verification, the journal,
  progress and cancellation.
- **[Changelog](https://github.com/stampla/stampla/blob/main/CHANGELOG.md)** —
  every release, hand-written.

Questions and bug reports:
[issues on GitHub](https://github.com/stampla/stampla/issues).
